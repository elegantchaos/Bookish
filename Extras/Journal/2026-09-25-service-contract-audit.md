# 2026-09-25 Service Contract Audit

The fifth and final service refactor pass checked every service against
[Decision 0022](../Decisions/0022-service-state-api-and-provider-shape.md).

`Services/` now contains only service files. The recognition-candidate and
record type-matching extensions moved to `Extensions/`. The import, storage, and
record-creation errors moved to `Errors/`. `BookishServiceConfiguration`,
`BookishImportWorkflowResult`, `CaptureGoodExample`, and the
`BookishImportEventReporter` typealias moved to the package root, one type per
file.

Contract findings and fixes:

- Each service implements only its own nested `API`. No service conforms to
  another capability protocol.
- Commands reach services only through `centre.xxxService`, which returns
  `any API`. The lookup provider property was renamed from `lookupWorkflow` to
  `lookupWorkflowService` to match the convention.
- `BookishPresentationService.API` had no command or collaborator users; the
  browser service uses the concrete presentation service. The protocol was
  removed, since the decision gives command-less services no `API`.
- Views receive only `State` projections and `BookishCommander` from the
  environment. Each `State` exposes reads, bindings, and view-owned wiring only.
- `BookishUIStateView` was renamed `BookishRootView`, and the engine's
  `presentationService` property was renamed `presentation` to match its
  siblings.

The BookishApp README and the command and environment design document were
updated to the finished shape.

## Validation tooling

Full validation had been failing at `test BookishLookup (macOS)` because
agt 3.6.0 treated project-referenced local packages as workspace roots and ran
their tests through autogenerated Xcode schemes, which have no test action.
AgentTools 3.6.1 tests such packages in their own directories. Updating agt and
discarding the stale discovery cache in `.build/agt` fixed it. The failure had
also hidden the tests of BookishApp, BookishCleanup, BookishImporter,
BookishRecognition, and BookishRecordView from full validation.
